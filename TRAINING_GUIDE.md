# Полное руководство по обучению ИИ-моделей для генерации карт osu!mania 4K

Данный документ представляет собой пошаговую инструкцию полного цикла: от загрузки большого объема сырых `.osz` архивов карт до предобработки, токенизации, запуска бенчмарка производительности (CPU vs GPU) и тренировки выбранной нейросетевой модели с сохранением чекпоинтов.

---

## 1. Архитектура системы (4 ИИ-модели)

В соответствии с техническим заданием (ТЗ), пайплайн авто-маппинга состоит из 4 специализированных ИИ-компонентов:

| № | Модель / ИИ | Входные данные | Выходные данные | Роль в системе |
|---|---|---|---|---|
| **1** | **SyncBPMOffsetModel** (Синхронизация) | 80-полосная мел-спектрограмма аудио | `BPM` (темп) и `Offset` (мс до первого удара) | Точное определение темпа и начальной точки отсчета тактов |
| **2** | **DynamicsSVModel** (Динамика & SV) | Мел-спектрограмма + профиль энергии | Непрерывная кривая `Slider Velocity` и триггеры тайминг-зон | Расстановка зеленых линий тайминга (ускорения на дропах, замедления на спокойных участках) |
| **3** | **ManiaPatternTransformer** (Ядро генерации нот) | Мел-спектрограмма, вектор сложности `Star Rating` (1.0–9.9), авторегрессионный контекст | 16 классов 4K-аккордов + длительности Long Note (LN) | Основной генератор нот и паттернов (стримы, джакки, корды, холды) |
| **3-Diff** | **ManiaDiffusion** (1D Latent Beatmap Diffusion) | Мультимодальные токены аудио (80 Mel + 12 Transients + 12 Chroma + 8 Vocal Emotion + 8 Dynamics) + Star Rating + Timestep | Непрерывный 12-канальный пиано-ролл тензор карты `[12, T]` | Неавторегрессионная диффузионная генерация всей карты целиком за 1 прогон (20-50 шагов DDIM, как в Stable Diffusion 1.5). Без exposure bias, без засыпаний и без спама по одной полосе |
| **4** | **DifficultyEvaluatorModel** (Валидатор сложности) | Последовательность нот и плотность паттерна | Расчетный `Star Rating` (SR) | Контроль качества и проверка строгого соблюдения целевой сложности в пределах $\pm 0.3$★ |

---

## 1.1. Источники данных: Обучение на оригинальных данных карты (Ground Truth)

При обучении **Модели 2 (Dynamics)** и **Модели 3 (Transformer)** критически важно, откуда берутся опорные данные сетки (BPM, Offset, SV, ноты):

1. **Режим эталонных данных карты (`--timing_source map`, включен ПО УМОЛЧАНИЮ):**
   - **BPM и Offset** извлекаются **напрямую из оригинального файла `.osu`** (независимо от первой модели).
   - **Кривые Slider Velocity (SV)** берутся строго из оригинальных зеленых тайминг-линий карты.
   - **Паттерны нот и Long Notes** берутся строго из HitObjects карты.
   - 🎯 **Преимущество:** Полная изоляция от погрешностей Модели 1. Модель 2 и Модель 3 обучаются на идеально чистых данных (Teacher Forcing), что гарантирует максимальную музыкальную выразительность и отсутствие дрейфа фазы.

2. **Каскадный режим (`--timing_source model1`):**
   - Использует предсказания первой модели (`SyncBPMOffsetModel`) для нарезки чанков на аудио. Позволяет проверить устойчивость трансформера к синтетическому дрейфу тайминга.

## 4. Шаг 2: Разбор карт на составные элементы (Препроцессинг & Токенизация)

Перед тренировкой нейросетей сырые аудиозаписи и текстовые `.osu` файлы необходимо превратить в тензоры PyTorch:
1. **Декодирование звука**: извлечение главного аудио-трека песни и конвертация через ffmpeg в 16 000 Гц моно `.wav`.
2. **Мел-спектрограмма**: расчет 80-полосной логарифмической мел-спектрограммы с шагом фрейма 16 мс (hop_length=256).
3. **16-классовая токенизация нот**: 
   Для 4 клавиш mania существует ровно $2^4 = 16$ дискретных состояний аккордов:
   - `0`: пустой фрейм (тишина / пауза)
   - `1`: клавиша 1 (`[1, 0, 0, 0]`)
   - `2`: клавиша 2 (`[0, 1, 0, 0]`)
   - `3`: двойной аккорд (`[1, 1, 0, 0]`)
   - ...
   - `15`: квадро-корд (`[1, 1, 1, 1]`)
4. **Маски Long Notes (LN)**: фиксация удержания лонг-нот по каждой из 4 колонок.
5. **Музыкальная нарезка по тактам и квадратам ходов (BPM & Offset)**:
   - **Устранение фазового сдвига (Phase Drift)**: куски времени берутся **не произвольно/хардкодно**, а привязываются строго к музыкальной сетке долей песни, отсчитываемой от `Offset` с шагом такта `bar_len_ms = 4 * (60000 / BPM)`.
   - **Точность до миллисекунды**: если дроп в песне начинается в `0:51:12:19` (`51121 мс`), то тактовая сетка падает ровно на эту долю без накопления погрешности.
   - **Контекст предыдущих ходов (`prev_tokens`)**: для каждого чанка сохраняется паттерн предыдущего такта/квадрата. Модель 3 (Трансформер) обучается строить новый квадрат с оглядкой на уже расставленные ноты предыдущего хода, обеспечивая плавность и музыкальную связность маппинга.

### Параметры нарезки (`--align_mode`):
- `--align_mode beat` *(по умолчанию)*: строго синхронизирует чанки с началом музыкальных тактов (downbeat) по BPM и Offset.
- `--bars_per_step 2`: шаг сдвига окна на 2 такта (полуквадрат) для высокой плотности обучения.
- `--align_mode frame`: классическое скользящее окно по фиксированному числу миллисекунд (для совместимости).

### 6.3. Запуск обучения ManiaDiffusion (1D Latent Beatmap Diffusion на 3x RTX 5060)

Новая архитектура диффузии генерирует всю карту целиком в неавторегрессионном режиме, устраняя засыпания в куплетах и спам нот. Обучение автоматически масштабируется на все доступные видеокарты (DataParallel на 3x RTX 5060) с батчем 64 на каждую карту:

```bash
# Быстрый запуск через скрипт (Windows):
train_diffusion.bat 100 64 0.0001

# Или прямой запуск через Python:
python train_diffusion.py \
    --epochs 100 \
    --batch_size 64 \
    --lr 0.0001 \
    --transfer_model3 checkpoints/model_3_transformer_best.pt \
    --cfg_dropout 0.15

# Возобновление обучения:
python train_diffusion.py --resume
```

#### Генерация карт через ManiaDiffusion:
```bash
# Генерация с выбором шагов DDIM (как в Stable Diffusion 1.5, например 30 шагов) и шкалы CFG:
python generate_beatmap.py --template "path/to/template.osz" --sr 3.6 --diffusion --steps 30 --cfg 3.0

# Пакетная генерация нескольких сложностей:
python generate_beatmap.py --template "path/to/template.osz" --sr 2.0,2.8,3.6,4.5,5.2 --diffusion --steps 25 --cfg 3.5
```

### 6.2. Детальный запуск через `train.py` (Авторегрессионный трансформер)

Для тонкой настройки параметров используйте аргументы командной строки:

```bash
# Обучение Модели 3 на оригинальных данных карты (Ground Truth - рекомендуется!)
python train.py \
    --model 3 \
    --device cuda \
    --dataset dataset_processed/train_data.pt \
    --timing_source map \
    --checkpoint_dir checkpoints \
    --epochs 25 \
    --batch_size 16 \
    --lr 0.0002 \
    --val_split 0.1
```

#### Параметры:
- `--model` (`-m`): `1` (sync), `2` (dynamics), `3` (transformer), `4` (evaluator), или `all`.
- `--timing_source` (`-t`):
  - `map` *(по умолчанию)*: **Оригинальные данные карты** — использует чистые оригинальные BPM, Offset, SV и HitObjects из `.osu` файла. Модель 2 и Модель 3 не зависят от ошибок первой модели и учатся на идеальных эталонных ритмических структурах.
  - `model1`: **Каскадный режим** — использует предсказанные Моделью 1 тайминги.
- `--resume` (`-r`): **Продолжить обучение ровно с момента остановки**. Восстанавливает веса модели, оптимизатор (AdamW momentum & moving averages), планировщик LR и номер эпохи, как будто паузы не было вовсе.
  - При вызове `--resume` без параметров автоматически ищет `model_X_last.pt` (или `model_X_best.pt`) в папке `checkpoints/`.
  - Можно передать явный путь: `--resume checkpoints/model_3_transformer_last.pt`.
- `--device` (`-d`): 
  - `cuda` (NVIDIA GPU с тензорными ядрами)
  - `mps` (Apple Silicon M1/M2/M3/M4 GPU)
  - `cpu` (многопоточный процессор)
  - `auto` (автоматический выбор лучшего доступного ускорителя)
- `--batch_size` (`-b`): размер пачки сэмплов (для CPU рекомендуется 8–16, для GPU 16–64).
- `--epochs` (`-e`): количество полных проходов по датасету (или добавочных эпох при продолжении).
- `--lr`: скорость обучения (learning rate), по умолчанию `0.0002`.

### 6.3. Пауза и бесшовное продолжение обучения (Resume)

Если у вас **прямо сейчас запущено обучение** или вы хотите в любой момент его остановить и продолжить позже:

1. **Безопасная остановка (Ctrl+C):**
   - Вы можете нажать `Ctrl + C` в консоли. Скрипт перехватит прерывание и **автоматически сохранит текущее состояние модели и оптимизатора** в файл `checkpoints/model_3_transformer_last.pt`.
   - Даже если процесс был завершен принудительно, в конце каждой завершившейся эпохи файл `_last.pt` всегда перезаписывается в актуальном виде.

2. **Запуск продолжения обучения:**
   - Чтобы продолжить ровно с того места, где обучение остановилось:
   ```bash
   # Через Python (авто-подхват последнего чекпоинта):
   python train.py --model 3 --resume

   # Через Bash-скрипт:
   ./train.sh 3 gpu 20 16 0.0002 map resume
   # или через переменную окружения:
   RESUME=1 ./train.sh 3 gpu 20 16

   # Через PowerShell:
   .\train.ps1 -Model 3 -Resume

   # В Windows CMD:
   train.bat 3 auto 20 16 0.0002 map resume
   ```

3. **100% Обратная совместимость:**
   - **Вам НЕ нужно начинать обучение заново!** Если ваш чекпоинт был сохранен старой версией скрипта (в которой сохранялись только веса без состояния оптимизатора), скрипт автоматически загрузит веса с нужной эпохи, безопасно инициализирует оптимизатор и продолжит тренировку без единой ошибки.
   - Если в чекпоинте уже есть состояние оптимизатора, восстанавливаются все градиентные моменты AdamW, благодаря чему кривая функции потерь продолжается абсолютно гладко, без скачков.

## 7. Чекпоинты и результаты обучения

Во время обучения скрипт непрерывно сохраняет два типа чекпоинтов в папку `checkpoints/`:
- **`model_X_last.pt`** — непрерывный слепок последней пройденной эпохи (включает состояние модели, оптимизатора и планировщика). Используется для бесшовного возобновления обучения (`--resume`).
- **`model_X_best.pt`** — наилучшая версия модели по валидационной метрике (наименьший Val Loss / Val MAE).

Список файлов чекпоинтов:
- `checkpoints/model_1_sync_best.pt` и `model_1_sync_last.pt` — веса модели синхронизации темпа
- `checkpoints/model_2_dynamics_best.pt` и `model_2_dynamics_last.pt` — веса модели динамики и SV
- `checkpoints/model_3_transformer_best.pt` и `model_3_transformer_last.pt` — веса генератора паттернов
- `checkpoints/model_4_evaluator_best.pt` и `model_4_evaluator_last.pt` — веса валидатора сложности

### Метрики, отслеживаемые в процессе:
- **Модель 3 (Трансформер)**: 
  - `Train Loss` / `Val Loss` — совместная функция потерь (CrossEntropy аккордов + BCE лонг-нот).
  - `Acc` (%) — процент точно угаданных 4K-конфигураций клавиш во временной сетке.
- **Модель 1 (Sync)**:
  - `BPM MAE` — средняя абсолютная погрешность определения темпа в ударах в минуту (целевое значение: < 1.0 BPM).
- **Модель 2 (Dynamics)**:
  - `SV MSE` — среднеквадратичная ошибка соответствия карты скоростей прокрутки.
- **Модель 4 (Evaluator)**:
  - `SR MAE` — точность попадания в целевой Star Rating (целевое значение: < 0.25★).

## 8. Тестирование сохранённых чекпоинтов (Инференс и Диагностика)

Для быстрой проверки обученных чекпоинтов на произвольном аудиофайле (`.wav`, `.mp3`, `.ogg`, `.flac`) или на сэмплах из обучающего датасета создан скрипт **`test_checkpoint.py`** (и его обёртки `.ps1`, `.bat`, `.sh`).

### 8.1. Тестирование Модели 1 на своем треке (MP3 или WAV):
```bash
# Через Python:
python test_checkpoint.py --model 1 --audio "path/to/song.mp3"

# В PowerShell:
.\test_checkpoint.ps1 -Model 1 -Audio "path\to\song.mp3"

# В Windows CMD:
test_checkpoint.bat 1 "path\to\song.mp3"

# В Git Bash / Linux:
./test_checkpoint.sh 1 "path/to/song.mp3"
```
**Что выдаст модель:**
- 🎯 **Предсказанный BPM** (например, `174.98 BPM`)
- ⏱️ **Предсказанный сдвиг первого удара (Offset)** (например, `42 ms`)
- 🎵 **Интервал долей** (мс между четвертями) и длина такта 4/4
- 🥁 **Таймкоды первых 8 ударов метронома**
- Сравнение с эвристическим спектральным анализом (при наличии WAV).

### 8.2. Тестирование Модели 1 на чанках датасета (сравнение с Ground Truth):
```bash
python test_checkpoint.py --model 1 --dataset dataset_processed/train_data.pt --num_samples 10
```
Выведет наглядную таблицу сравнения:
- Реальный BPM из карты (`True BPM`) vs Предсказанный моделью (`Pred BPM`) и абсолютная ошибка
- Реальный Offset (`True Off`) vs Предсказанный моделью (`Pred Off`)
- Средняя абсолютная ошибка MAE по всем проверенным сэмплам.

### 8.3. Тестирование других моделей:
```bash
# Модель 2: Тест генерации кривой скорости SV
python test_checkpoint.py --model 2 --audio song.mp3

# Модель 3: Тест генерации аккордов Трансформером на участке трека с заданной сложностью
python test_checkpoint.py --model 3 --audio song.mp3 --sr 4.5
```

## 9. Использование обученной модели для генерации карт

После завершения обучения сохраненный чекпоинт готов к генерации новых карт из любого аудиофайла:

```bash
# Генерация карты 4.5★ из нового трека song.mp3
python3 -m osu_mapper.pipeline \
    --audio "my_new_track.mp3" \
    --title "My Generated Beatmap" \
    --artist "Cool Artist" \
    --diff "4.5" \
    --checkpoint "checkpoints/model_3_transformer_best.pt" \
    --output "output_maps/generated_map.osz"
```

Готовый файл `.osz` можно сразу открыть двойным кликом в клиенте osu! и играть.

## 9. Частые вопросы и решение проблем (FAQ & Troubleshooting)

### В: Ошибка `[WinError 2] Не удается найти указанный файл` при обработке архивов
**О:** Данная ошибка в Windows возникает, когда скрипт пытается вызвать внешнюю утилиту `ffmpeg`, но исполняемый файл `ffmpeg.exe` не найден.
**Решение:**
1. Скачайте `ffmpeg.exe` (например, zip-архив с [ffmpeg.org](https://ffmpeg.org/download.html)).
2. Скопируйте файл `ffmpeg.exe` прямо в папку `ffmpeg/` в корне проекта (`AIManiaMapper4k\ffmpeg\ffmpeg.exe`). Скрипт автоматически найдет его там.
3. Либо укажите путь через флаг:
   ```powershell
   python prepare_dataset.py --ffmpeg "C:\Users\...\ffmpeg.exe"
   ```

### В: Как запускать скрипты в Windows PowerShell?
**О:** Для всех операций созданы нативные `.ps1` (PowerShell) и `.bat` скрипты:
- Препроцессинг: `.\prepare_dataset.ps1` (или `prepare_dataset.bat`)
- Бенчмарк: `.\benchmark.ps1 -Model 3` (или `benchmark.bat 3`)
- Обучение: `.\train.ps1 -Model 3 -Device cuda -Epochs 20` (или `train.bat 3 cuda 20`)

### В: Что делать при ошибке `CUDA out of memory` (OOM)?
**О:** Память видеокарты переполнена. Уменьшите размер батча:
```bash
./train.sh 3 gpu 20 8    # уменьшите batch_size с 16 до 8 или 4
```

### В: Можно ли прервать обучение комбинацией Ctrl+C?
**О:** Да. Лучший чекпоинт (`*_best.pt`) сохраняется сразу же после каждой успешной эпохи, поэтому достигнутый прогресс не потеряется.

### В: Как дообучить модель на новых картах?
**О:** 
1. Положите новые `.osz` файлы в `sample beatmaps/`.
2. Запустите `.\prepare_dataset.ps1` (или `./prepare_dataset.sh`), чтобы обновить `train_data.pt`.
3. Запустите `.\train.ps1 -Model 3 -Device cuda -Epochs 15` (или `./train.sh 3 gpu 15 16`).
