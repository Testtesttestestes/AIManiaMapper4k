# Техническое задание (ТЗ): ИИ-генератор карт osu!mania 4K

## 1. Назначение и область применения

Разработка автоматизированного пайплайна (AI Mapper) для генерации игровых уровней (карт) ритм-игры osu! в режиме mania 4K. Система принимает на вход музыкальный файл и целевую сложность, а на выходе формирует готовый к импорту архив `.osz`. Генерация базируется на ансамбле нейросетевых моделей, обучаемых на существующей базе пользовательских карт.

## 2. Входные и выходные данные

* **Входные данные:**
* Аудиофайл в формате `.wav`.
* Целевая сложность (Star Rating): число с плавающей точкой в диапазоне от 1.0 до 9.9.


* **Выходные данные:**
* Готовый файл `.osz`, содержащий аудио, сгенерированный файл `.osu` с метаданными, таймингами и объектами (hit objects), а также необходимые ресурсы (фон и т.д.).



---

## 3. Архитектура системы

Процесс разделен на модуль подготовки данных (обучение) и трехступенчатый инференс-пайплайн (генерация).

| Модуль | Задача | Вход | Выход |
| --- | --- | --- | --- |
| **Экстрактор (Data Prep)** | Парсинг папки `sample beatmaps`, извлечение `.osu` файлов | `.osz` архивы | Структурированный датасет (спектрограммы, BPM, паттерны, SV) |
| **Модель 1 (Синхронизация)** | Определение базового темпа и начального смещения | `.wav` аудио | `BPM` (уд/мин), `Offset` (мс) |
| **Модель 2 (Динамика)** | Расстановка Timing Points (изменения скорости, SV-зоны) | `.wav`, `BPM`, `Offset` | Массив Timing Points (ускорения/замедления) |
| **Модель 3 (Маппинг)** | Расстановка нот (Hit Objects) с учетом контекста и сложности | `.wav` (чанки), тайминги, Star Rating | Массив Hit Objects (ноты, лонг-ноты) |
| **Сборщик (Packager)** | Сборка всех сгенерированных данных в финальный архив | Метаданные, объекты, `.wav` | Рабочий `.osz` файл |

---

## 4. Функциональные требования к компонентам

### 4.1. Модуль экстракции данных (Обучающая выборка)

* Система должна распаковывать `.osz` файлы из директории `sample beatmaps`.
* Необходимо парсить файлы `.osu` (режим `Mode: 3` — mania, `CircleSize: 4` — 4K).
* Извлекаемые факторы для обучения: плотность нот, паттерны (джек, стрим, джампстрим), использование лонг-нот (LN), привязка к музыкальным транзиентам (kick, snare, hi-hat), значения Slider Velocity (SV).

### 4.2. Модель 1: BPM и Offset (Аудио-анализ)

* Анализ ритмической сетки `.wav` файла.
* Определение первого сильного удара (Offset) с точностью до миллисекунды.
* Вычисление базового BPM (включая мульти-BPM треки, если требуется).

### 4.3. Модель 2: Timing Zones и SV (Динамика карты)

* Генерация `Inherited Timing Points` (зеленые линии) для создания визуальной динамики.
* Анализ энергии аудиосигнала для расстановки ускорений (на дропах/кульминациях) и замедлений (на спокойных участках/бриджах).

### 4.4. Модель 3: Генерация паттернов (Ядро)

* **Идеальная синхронизация:** Модель должна обрабатывать аудио короткими отрезками (чанками), границы которых строго детерминированы таймингами из Модели 1 и 2. Размещение нот должно происходить с абсолютной миллисекундной точностью (например, транзиент на `00:51.121` должен порождать ноту строго на `51121` мс).
* **Контроль сложности (Conditioning):** Архитектура модели должна принимать Star Rating (1.0 - 9.9) как глобальный тензор условий. Модель обязана ограничивать плотность нот и сложность паттернов (NPS - Notes Per Second) в соответствии с заданным параметром.
* **Удержание контекста (Context Window):** ИИ должен использовать авторегрессионный подход или механизм внимания (Self-Attention/Transformers) для запоминания *N* предыдущих сгенерированных тактов/паттернов. Это необходимо для сохранения музыкальной и игровой логики (избежание нечитаемого "спама" нот, логичное завершение стримов и джеков).

### 4.5. Модуль сборки (Packager)

* Генерация валидного синтаксиса `.osu` формата (v14).
* Автоматическое заполнение секций `[General]`, `[Metadata]`, `[Difficulty]`, `[TimingPoints]`, `[HitObjects]`.
* ZIP-компрессия в расширение `.osz`.

## 5. Точность и требования к тестированию (Unit Tests)

Ввиду критичности ритмической точности, система должна покрываться автоматическими тестами.

* **Тест абсолютной привязки (Audio Alignment Test):** Юнит-тест, подающий на вход синтетический `.wav` с резкими импульсами (кликами) на известных таймингах (например, ровно на `51121` мс). Тест проверяет, что Модель 3 генерирует `HitObject` с таймингом, дельта которого от целевого не превышает `±2 мс`.
* **Тест соблюдения сложности (Star Rating Validation):** Сгенерированная карта прогоняется через стандартный алгоритм osu! (osu-tools/Performance Calculator). Итоговый SR сгенерированной карты не должен отклоняться от запрошенного пользователем более чем на `±0.3` звезды.
* **Тест синтаксиса:** Проверка собранного `.osz` на парсинг официальным клиентом игры (отсутствие крашей, ошибок импорта).

## 6. Рекомендуемый стек технологий

* **Работа с аудио:** `librosa` или `torchaudio` (извлечение мел-спектрограмм, onset detection, CQT).
* **Машинное обучение:** `PyTorch`.
* *Модель 1 & 2:* 1D-CNN + RNN или Wav2Vec для анализа временных рядов.
* *Модель 3:* Transformer-based архитектура (по аналогии с языковыми моделями, где "токенами" выступают комбинации 4 клавиш) с condition-вектором для сложности.


* **Парсинг osu:** Использование существующих библиотек (например, `slider` (Python) или `osrparse`/кастомный парсер для `.osu` синтаксиса).

## 7. Практическое руководство и запуск

### 7.1. Установка зависимостей
```bash
# Python зависимости
pip install -r requirements.txt

# Запуск веб-панели управления
npm install
npm run dev
```

### 7.2. Команды запуска CLI

#### Извлечение метаданных из архивов карт (Dataset Extractor)
```bash
# Сканирует 'sample beatmaps/', парсит только Mode 3 (mania) и 4K (CircleSize 4),
# и сохраняет manifest.json и manifest.csv в dataset_manifest/
python3 extract_dataset.py "sample beatmaps" "dataset_manifest"
```

#### Генерация карты osu!mania 4K (End-to-End Pipeline)
```bash
# Генерация на основе реального аудиофайла:
python3 generate_beatmap.py path/to/song.wav --sr 4.5 --output output_beatmaps/my_map.osz

# Быстрая генерация с синтетическим ритмическим треком:
python3 generate_beatmap.py --synthetic --duration 30 --sr 3.8 -o output_beatmaps/synth_map.osz

# Запуск с ручной фиксацией BPM и Offset:
python3 generate_beatmap.py song.wav --bpm 175.0 --offset 48 --sr 5.2
```

#### Запуск набора автоматических тестов
```bash
python3 -m unittest discover tests/ -v
```

## 8. Возможности и явные ограничения Baseline-генератора

### Возможности текущего Baseline:
1. **Абсолютная привязка к транзиентам:** Детекция фронтов сигнала (spectral flux) с абсолютным попаданием в ноты (допуск $\le \pm 2$ мс; в тестах достигается точность 0 мс).
2. **Контроль сложности (Star Rating Conditioning):** Непрерывное масштабирование параметров плотности (NPS), распределения аккордов (Single, Jump, Hand, Quad) и вероятности Long Notes от 1.0 до 9.9 звезд.
3. **Расчет SV-динамики:** Автоматическая генерация `Inherited Timing Points` (зеленые линии) на основе локального RMS-энергетического профиля аудио.
4. **Соблюдение спецификации osu! v14:** Корректные секции `[General]`, `[Metadata]`, `[Difficulty]`, `[TimingPoints]`, `[HitObjects]` (X-координаты 64, 192, 320, 448 для 4K) и валидная ZIP `.osz` компрессия.
5. **Нейросетевое ядро:** Модуль `osu_mapper.models.transformer.ManiaPatternTransformer` с токенизацией 16 комбинаций 4K клавиш и каузальным вниманием.

### Явные ограничения Baseline:
1. **Эвристический генератор паттернов в Baseline:** Инференс в CLI по умолчанию использует эвристическо-статистический генератор паттернов с квантованием сетки и anti-finger-trap правилами; полноценная авторегрессионная генерация весов через `ManiaPatternTransformer` требует предварительного обучения чекпоинта на собранном датасете.
2. **Ограничение по мульти-BPM:** Анализатор базового ритма в текущей версии рассчитывает доминирующий темп трека; комплексные полиритмические композиции с частыми изменениями темпа требуют ручной спецификации дополнительных тайминг-секций.
3. **Anti-Spam / Anti-Jack ограничения:** В baseline введены жесткие ограничения на частоту повтора одной и той же клавиши (anti-jack) во избежание неиграбельных карт на высоких SR.
