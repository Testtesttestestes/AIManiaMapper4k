# Обучение нейросети AIponchik

Нейросеть сейчас **не используется в `game_parser.py` во время анализа экрана**. Это отдельный экспериментальный pipeline: он генерирует обучающие партии в симуляторе, учит модель ранжировать возможные ходы и сохраняет JSON-артефакт, который позже можно будет подключить отдельным PR.

## Быстрый запуск

```bat
scripts\train_policy_network.bat
```

То же самое из терминала:

```bash
python train_policy_network.py --out models/policy_network.json --metrics-out run_outputs/policy_training_metrics.json
```

По умолчанию скрипт теперь **пытается сыграть 210 training-игр и 70 validation-игр**, потому что проигрышные партии teacher отбрасываются целиком и не попадают в датасет.

После завершения будут обновлены:

- `models/policy_network.json` — веса сети, список признаков, нормализация, training config и метрики;
- `run_outputs/policy_training_metrics.json` — те же метрики отдельным файлом для просмотра.

## Как продолжить/усилить тренировку

Для более долгого прогона увеличивай число обучающих и проверочных игр:

```bash
python train_policy_network.py ^
  --train-games 210 ^
  --val-games 70 ^
  --eval-games 50 ^
  --epochs 160 ^
  --hidden-units 64 ^
  --dropout 0.10 ^
  --l2 0.0007 ^
  --target-win-rate 60 ^
  --out models/policy_network.json ^
  --metrics-out run_outputs/policy_training_metrics.json
```

По умолчанию генератор теперь обучает модель **только на выигранных партиях учителя**: если эвристический teacher не закрыл цели, все ходы этой партии отбрасываются и не попадают в датасет. Это отсеивает проигрышные траектории и уменьшает риск, что сеть будет копировать стратегии, которые привели к поражению. Если для диагностики нужно вернуть старое поведение, добавь `--include-losing-games`.

Рекомендации против переобучения:

1. Из-за отбора только победителей увеличивай `--train-games` и `--val-games`: часть партий будет отброшена, а метрики `trainGamesKept` / `valGamesKept` покажут, сколько победных историй реально попало в обучение, а `trainGamesDiscarded` / `valGamesDiscarded` — сколько проигрышных партий было отброшено до добавления в общий датасет.
2. Не выключай `dropout` и `l2`, если `trainTop1Agreement` заметно выше `valTop1Agreement`.
3. Меняй `--seed`, чтобы проверить, что модель держится на других случайных полях.
4. Смотри не только `valTop1Agreement`, но и `policyEvaluation.successRate`: именно это процент побед в симуляции.
5. Проверяй гибрид в честном сравнении: `--blend-heuristic 0.5` часто сглаживает ошибки модели и эвристики лучше, чем чистая политика.

## Честный бенчмарк и blend

Для сравнения алгоритма, чистой нейронки и гибрида на одних и тех же стартовых данных используй:

```bash
python compare_policy_benchmark.py --games 50 --base-seed 20260601 --blends 0.0,0.5 --out run_outputs/policy_benchmark_comparison.json
```

Скрипт запускает каждую стратегию на одинаковых партиях: для игры `i` используется seed `base-seed + i`, поэтому уровень, сложность, стартовая доска и лёд совпадают между алгоритмом и нейронкой. В отчёте `deltaVsAlgorithm` показывает, пробил ли чистый policy/blend потолок эвристики.

## Поля на тренировке случайные?

Да. Тренировка берёт эталонные JSON из `etalon_images` только как шаблоны реальных уровней: цели, лимиты ходов, примерную частоту фишек и льда. Сами игровые поля для каждой обучающей партии создаются заново случайно детерминированным генератором NumPy по `--seed`; validation и post-training evaluation используют другой seed, чтобы не проверяться на тех же самых партиях.

## Текущий статус 60% побед

Скрипт теперь после обучения автоматически запускает `--eval-games` партий нейросетью и пишет `policyEvaluation.successRate`. Я запустил текущий pipeline на 50 held-out партиях с `--target-win-rate 60`: модель получила `9/50` побед (`18.0%`), поэтому в `models/policy_network.json` сейчас стоит `targetReached=false`. Это значит, что цель 60% ещё не достигнута, и модель пока нельзя подключать к анализатору как основную. Следующий шаг — улучшать teacher-labels/симулятор и только потом повторять длинную тренировку.

## Подбор эвристических весов Optuna

Для текущего эвристического бота добавлен отдельный оптимизатор весов. Он запускает полные симулированные партии и максимизирует процент побед; при установленной `optuna` используется TPE/байесовская оптимизация, иначе скрипт делает детерминированный random-search fallback.

```bash
python tune_heuristic_weights.py --trials 40 --games-per-trial 50 --out run_outputs/heuristic_tuning.json
```

Полезные параметры:

- `--search-depth 2` — рекомендуемая глубина дерева воображаемых ходов; при сильном RNG глубина 3 обычно дороже, чем полезнее;
- `--rollout-samples 12` — число случайных заполнений `EMPTY` клеток для вероятностной оценки; лучше расширять выборку RNG, а не углублять дерево;
- `--max-paths-per-item 15` — ограничение ширины дерева, чтобы live-режим и долгие прогоны оставались управляемыми.

Основной анализатор использует вероятностный lookahead по умолчанию (`search_depth=2`, `rollout_samples=12`, `max_paths_per_item=15`), а быстрые симуляционные smoke-тесты могут отключать rollout через `rollout_samples=0`. Симулятор сохраняет честные множители сложности для `normal` и `hard`, поэтому рост винрейта не должен достигаться скрытым снижением целей или добавлением ходов.
